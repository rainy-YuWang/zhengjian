## AI参与的工作

需求拆解、标的选择、信息架构、证据状态设计、前端和后端代码、公式与数据结构、测试、文档和浏览器检查均由本会话中的AI完成。未使用子代理，未生成图片，未将AI文字伪装为原始披露。

产品中的解释文案是AI参与撰写的固定核验解读。运行时默认没有在线模型调用；不能把点击“开始诊断”描述为每次都由大模型实时生成。可选模型只在服务端选择和排序合法证据ID。

## 核验与修正

| 初始风险或实现问题 | 处理与验证 |
|---|---|
| 凭模型记忆使用旧财报 | 改为检索2026三季报与2025年报摘要，标明报告期和核验日 |
| 合并现金流增加被简单理解为需求改善 | 阅读报告第3页原因，拆成数值事实、公司解释与分析限制；E02保留矛盾 |
| 营业总收入与营业收入混用 | 使用利润表营业收入，不含财务公司利息收入；毛利率指定口径 |
| 合同负债较年初下降被误写成同比 | 明确为2026-09-30相较2025-12-31，不将下降直接等同信心下降 |
| 公司库存陈述被误认为独立事实 | 标记为待验证，并要求独立库存、动销或批价证据 |

| 构建时语法和类型错误 | 修复JSON请求闭合与维度类型，重跑类型检查和构建 |

这里记录的是AI自检与工程修正，不声称候选人已经人工复核。当前会话没有候选人逐项审稿或独立重做财报抽取的记录；提交者应在提交前按实际情况补充自己的审阅、修改和理解，不能编造人工验证。

## 证据验证方法

优先读取公司/巨潮/交易所披露；检索结果仅用于定位。收入、利润、现金流、营业成本从相应报告页读取后保存原始元金额。核心同比由纯函数重算，测试与披露四舍五入值对照。财务解释核查上下文而非只看搜索摘要。来源、页码和计算公式随证据一起交付。

可选OpenAI接口依据官方Responses API文档实现。真实在线调用没有API凭据，未实际执行；mock只证明适配和回退逻辑，不能证明生产账号、模型名、权限或配额可用。没有声称接通过扶摇或iFinD。

## 提示词与输出约束

服务端指令要求：用户文本视作不可信问题；仅选择已有证据ID；返回claimIds数组；不输出自由文本、数字预测或交易建议。服务器验证所有ID在候选集合内、1–8项、无重复，然后由已核验文案渲染。即使注入试图改变规则，未知文本也不进入产品诊断结论。
